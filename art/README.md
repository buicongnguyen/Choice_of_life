# Choice of Life art pipeline

All 3D art is generated by Python scripts running in Blender 4.5 (headless). Nothing is hand-edited,
so every asset can be rebuilt, reviewed and changed in code.

```sh
BLENDER=<path to blender.exe>
"$BLENDER" --background --factory-startup --python art/build.py -- [group|name ...]   # -> art/.raw/*.glb + sidecars
node art/pack.mjs [group|name ...]                                                    # -> public/models/*.glb + manifest.json
PREVIEW=out.png "$BLENDER" --background --factory-startup --python art/build.py -- name1 name2   # render, no export
```

- `kit.py` — materials (vertex "painted light" x colour), bevelled primitives, joining, painting, export.
- `characters.py` — people bodies, hair, accessories, Biscuit the dog.
- `sets/<place>.py` — one module per place kit. Each exposes `registry() -> {asset_name: (group, builder)}`,
  where `builder(kit)` builds one asset into the empty scene and returns its root object.
  Files starting with `_` are helpers and are not scanned.
- `pack.mjs` — gltfpack (meshopt, quantised) keeping node names, material names and extras.

## Look

Mario Kart 8 quality bar for stylised toy art, never copied designs: chunky forms, soft bevels on every
edge, glossy saturated colour, readable silhouettes, dense dressing. Warm and vivid, never pastel or
beige-dominated. Use `kit.PALETTE` names (coral, marigold, teal, ocean, leaf, berry, sky, cream, plum...).
Roughness: `GLOSS` (.32) for painted toys and plastic, `SATIN` (.5) for fabric and wood, `MATTE` (.72)
for stone, soil and asphalt. Call `kit.paint(objects)` on the finished asset so the base is shaded and
cool and the top is warm (`k.join()` then `k.paint([obj])`).

## Space and scale (1 unit = 1 metre)

The game is a side-on diorama. The player runs toward **+X**; the camera looks at the scene from **-Y**
(Blender), about 13 m away and 4.5 m up, with a 38° vertical field of view. Blender -Y becomes Three.js
+Z (toward the camera).

| Band | Blender Y | What goes there |
|---|---|---|
| Foreground | -6 … -3.4 | Only low dressing (< 0.8 m tall): flowers, low fences, kerbs, rocks. |
| Lanes | -2.8 … +2.8 | The three running lanes are at Y = -1.9, 0, +1.9. Hazards and pickups live here. |
| Backdrop | +3.5 … +10 | Buildings, furniture against walls, trees. Fronts face -Y and start near Y = +3.5. |
| Far | +20 … +120 | Big simple silhouettes: hills, sea, skyline, cliffs. |

- Props: origin at the centre of the footprint, base at Z = 0, front facing -Y.
- Ground tiles are exactly **8 m long in X**, centred on X = 0, and tile seamlessly.
- An adult person is about 1.5 m tall, a child 1.1 m. Doors ~2.1 m, houses 5–8 m tall.

## Runtime material names

Materials are recoloured or animated by name, so keep these exact names when the effect is wanted:

| Name | Runtime meaning |
|---|---|
| `Window` | Glass that glows warm at dusk and in the storm (emissive boost). |
| `Lamp` | Light bulbs and lantern glass (always emissive; brighter at night). |
| `Water` | Replaced by the animated sea/puddle shader. |
| `Skin`, `Hair`, `Top`, `Bottom`, `Shoes`, `Accent` | Character recolour slots. |

Keep each asset to 8 or fewer materials; reuse names within an asset.

## Budgets

| Asset | Triangles | Packed size |
|---|---|---|
| Small prop / pickup / hazard | ≤ 1,500 | ≤ 40 KB |
| Building / large prop | ≤ 5,000 | ≤ 120 KB |
| Hero (lighthouse) | ≤ 10,000 | ≤ 200 KB |

The whole `public/models` folder should stay under 6 MB.

## Contracts checked by tests

`public/models/manifest.json` records every asset's group, bytes, triangles, node names, material names
and root extras. `game/src/render/assets.test.ts` checks that the assets the game uses exist, that joints
and sockets are present, and that budgets hold.
